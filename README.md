# netspeed

Консольный скрипт, который замеряет скорость скачивания с заданного адреса. Делает 10 запросов подряд, на каждый ждёт ответ целиком, потом печатает среднее время запроса, общий объём и скорость.

Помимо общего времени скрипт раскладывает каждый запрос по этапам: поиск адреса (DNS), подключение (TCP), шифрование (TLS), ожидание ответа сервера и само скачивание. По этой разбивке видно, куда уходит время: в канал, в рукопожатия или в медленный сервер.

Нужен Python 3.8 или новее. Сторонние библиотеки не используются, устанавливать ничего не нужно.

## Запуск

```bash
git clone https://github.com/getrismine/netspeed.git
cd netspeed
python3 netspeed.py "https://speed.cloudflare.com/__down?bytes=10000000"
```

На Windows вместо `python3` пишется `python`. Адрес лучше брать в кавычки: в нём бывают символы `?` и `&`, которые иначе перехватит командная строка.

Адреса, на которых удобно проверять:

| Адрес | Размер |
|---|---|
| `https://speed.cloudflare.com/__down?bytes=10000000` | любой, задаётся параметром `bytes` |
| `https://proof.ovh.net/files/10Mb.dat` | 10 МиБ |
| `https://ash-speed.hetzner.com/100MB.bin` | 100 МБ |

### Параметры

| Параметр | Что делает |
|---|---|
| `url` | адрес, который скачиваем (обязательный) |
| `-n`, `--count` | сколько запросов сделать, по умолчанию 10 |
| `-t`, `--timeout` | сколько секунд ждать сеть, прежде чем выдать ошибку, по умолчанию 30 |
| `--no-cache-bust` | не добавлять к адресу случайный параметр (см. ниже) |
| `--json` | вывести результат в JSON, чтобы его могла прочитать другая программа |

Код выхода: `0` если всё скачалось, `1` при ошибке сети или сервера, `2` при неправильных параметрах.

## Единицы измерения

| Что | Единица | Перевод |
|---|---|---|
| Скорость, основная | Мбит/с (мегабиты в секунду) | 1 Мбит = 1 000 000 бит |
| Скорость, в скобках | МБ/с (мегабайты в секунду) | 1 МБ = 1 000 000 байт, 1 МБ/с = 8 Мбит/с |
| Объём | Б, КБ, МБ | 1 КБ = 1000 байт, 1 МБ = 1000 КБ |
| Время | мс (миллисекунды) и с (секунды) | 1 с = 1000 мс |

Мбит/с выбраны основной единицей, потому что в них указывают скорость тарифы провайдеров и сайты вроде Speedtest. МБ/с показывают браузеры и менеджеры загрузок, поэтому они стоят рядом. Приставки десятичные (1000, без 1024), как у провайдеров.

## Как считается

Скорость скачивания (главная цифра):

```
скорость = общий объём / суммарное время всех запросов
```

Это равно объёму, делённому на (среднее время запроса × число запросов). Время запроса считается от начала поиска адреса до последнего полученного байта.

Чистая скорость: тот же объём, делённый только на время, пока шло тело ответа. Подключение, шифрование и ожидание сервера сюда не входят. Чем меньше файл, тем сильнее расходятся две цифры: на файле в 100 КБ рукопожатия могут занимать больше времени, чем сама передача.

Время запроса печатается средним, как требует задание, и рядом медианой, минимумом, максимумом и стандартным отклонением. Среднее сильно портит один застрявший запрос, медиана к нему почти нечувствительна. В примере ниже это хорошо видно.

### Почему каждый запрос открывает новое соединение

Скрипт сам находит IP-адрес, сам подключается и сам включает шифрование, а готовое соединение передаёт стандартному `http.client`. Иначе этапы не получилось бы засечь по отдельности. После ответа соединение закрывается, следующий запрос проходит весь путь заново. Так все 10 запросов измеряются одинаково.

### Защита от искажений

- К адресу дописывается случайный параметр `_nocache=...`, новый на каждый запрос. Для сервера и CDN это каждый раз другой адрес, и отдать готовую копию из кэша они не могут. Подписанные ссылки (например, из облачных хранилищ) от лишнего параметра ломаются, для них есть `--no-cache-bust`.
- Заголовок `Accept-Encoding: identity` просит сервер не сжимать ответ. Со сжатием по сети прошло бы меньше байт, чем весит файл, и скорость получилась бы завышенной.
- Заголовки `Cache-Control: no-cache` и `Pragma: no-cache` просят промежуточные кэши не подсовывать сохранённую копию.
- Если сервер прислал меньше байт, чем обещал в `Content-Length`, это считается ошибкой. Стандартный `http.client` в такой ситуации молча возвращает то, что успел получить, поэтому проверка сделана отдельно.
- Переадресации (коды 301, 302, 303, 307, 308) отрабатываются, но не больше пяти подряд. Их время входит во время запроса.
- Ответ с кодом 400 и выше останавливает замер: скорость скачивания страницы с ошибкой ничего не говорит о канале.

## Тесты

```bash
python3 -m unittest -v
```

Тесты в интернет не ходят. Они поднимают на этом же компьютере маленький HTTP-сервер, который отдаёт файл известного размера, и проверяют, что скрипт насчитал ровно столько байт, прошёл по переадресации, заметил оборванный ответ, отправил нужные заголовки и правильно перевёл единицы.

## Ограничения

- Системный HTTP-прокси (переменные `HTTPS_PROXY` и подобные) не используется, скрипт подключается к серверу напрямую.
- Запросы идут по HTTP/1.1 в одно соединение. Speedtest и похожие сервисы качают в несколько потоков сразу, поэтому на быстрых каналах они покажут больше.
- Замеряется только скачивание, отдача на сервер не проверяется.
